# Cycle - agent guide

Private, local-first iOS period & cycle tracker (SwiftUI). All health data stays
on-device (SwiftData); no backend. Pro features are gated behind a StoreKit
in-app purchase. Ships a home-screen widget and Face ID app lock.

## Stack

- SwiftUI + SwiftData (iOS 17 deployment target), Swift 5.9. Built with Xcode 26 / iOS 26 SDK.
- The Xcode project is **generated by XcodeGen** from `project.yml` - `*.xcodeproj` is gitignored, never commit or hand-edit it.
- Four targets: `Cycle` (app), `CycleTests` (XCTest unit tests), `CycleUITests` (UI tests), `CycleWidgetExtension` (WidgetKit).
- Frameworks: HealthKit, StoreKit 2, WidgetKit, LocalAuthentication (Face ID).

## Setup / build / run

```sh
brew install xcodegen        # once
xcodegen generate            # regenerate Cycle.xcodeproj after any project.yml or file add/remove
open Cycle.xcodeproj         # then build/run in Xcode (Cmd-R)
```

Run `xcodegen generate` whenever you add/remove source files or edit `project.yml`;
new files under `Cycle/`, `CycleTests/`, `CycleWidgetExtension/` are picked up by
directory globs, so you rarely edit the project by hand.

## Test

```sh
xcodegen generate
UDID=$(xcrun simctl list devices available | grep -E "iPhone" | grep -Eo "[0-9A-Fa-f]{8}-[0-9A-Fa-f-]{27}" | head -1)
xcodebuild test -project Cycle.xcodeproj -scheme Cycle \
  -destination "platform=iOS Simulator,id=$UDID" CODE_SIGNING_ALLOWED=NO
```

30 XCTest cases across `CycleTests/` cover the pure logic (cycle derivation,
prediction, date math, export, models, shared-data handling). Pin the simulator to a runtime the host
actually has installed (`OS=<version>`); with only `name=`/`OS:latest`, xcodebuild
falls back to a device destination and fails if the matching sim runtime is absent.

## Conventions

- Services are stateless `enum` namespaces with static methods (`CycleCalculator`,
  `PredictionEngine`, `SharedData`, `NotificationManager`, `ExportManager`); stateful
  ones are `@MainActor @Observable final class` (`StoreManager`, `AppLockManager`, `HealthKitManager`).
- Models (`Cycle/Models/`) are SwiftData `@Model` types; register new persisted
  models in `CycleApp.swift`'s `.modelContainer(for:)`.
- Keep all cycle math testable and UI-free: put it in a Service, not a View.

## Sharp edges

- **App group is load-bearing.** App and widget share data through
  `UserDefaults(suiteName: "group.com.cycleapp.shared")` via `Cycle/Services/SharedData.swift`,
  which is compiled into *both* the app and the widget target (see `project.yml`).
  The widget only refreshes when the app calls `SharedData.update(...)` +
  `WidgetCenter.reloadAllTimelines()` on backgrounding (`ContentView.updateWidgetData`).
- **Entitlements are real:** HealthKit + the `group.com.cycleapp.shared` app group.
  Device/TestFlight builds need a provisioning profile with both. Simulator test
  builds work with `CODE_SIGNING_ALLOWED=NO`.
- Pro gating flows through `StoreManager.isPro` (product id `com.cycleapp.pro`);
  guard Pro-only UI on it, don't re-check StoreKit ad hoc.
- SDK is iOS 26 but deployment target is iOS 17 - don't introduce APIs newer than iOS 17.
